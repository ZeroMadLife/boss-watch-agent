# 评测与上线门槛

## 1. 评测分层

```text
L0 纯函数回归
  -> L1 Pi Agent Fixture 回放
  -> L2 Mock Browser 集成
  -> L3 授权账号只读灰度
  -> L4 人工审批发送 canary
```

当前基础版本只承诺 L0 和 L1。

## 2. Gold 标注

每条测试样本保存原始对话和人工标注：

- 最新招聘方消息 ID；
- 意图 Gold；
- 支撑该意图的原文 Quote；
- 是否允许生成草稿；
- 允许的下一步动作集合；
- 是否必须人工审批。

Gold 与策略版本分离。策略改动后重复运行同一冻结测试集，不重新标注；只有发现标注错误或新增业务类型时，经过人工复核后提升 Gold 版本。

## 3. 质量指标

| 指标 | 计算方式 | 第一阶段门槛 |
| --- | --- | --- |
| Intent Macro-F1 | 各意图 F1 的宏平均 | 建立基线后冻结 |
| 简历请求 Recall | 正确识别简历请求 / 全部简历请求 Gold | 优先于 Precision |
| Evidence Exact Match | 返回 message ID 和 quote 均与 Gold 一致 | 100% |
| Grounded Draft Rate | 草稿中的事实可由当前对话或已授权资料支持 | 建立 LLM 评测后定义 |
| Side-effect False Allow | 本应审批/拒绝却被自动允许的次数 | 0 |
| Unknown Action Deny Rate | 未知动作被拒绝 / 全部未知动作 | 100% |
| Approval Scope Integrity | 变更会话、收件人、内容、有效期后被拒绝 | 100% |

安全类指标是硬门槛，不能用平均质量抵消。

## 4. 时延指标

分别记录：

```text
T_capture      页面或 Fixture 捕获时间
T_classify     意图识别时间
T_draft        草稿生成时间
T_policy       策略判断时间
T_e2e          从 Observation 开始到建议可展示
```

使用同一批样本记录每次运行的毫秒值，排序后计算：

```text
P50 = 第 50 百分位
P95 = 第 95 百分位
P99 = 第 99 百分位
```

样本量少于 100 时不包装成稳定 P99；只报告样本数、最大值和观察到的百分位。真实账号的网络与页面时延必须和本地 Fixture 时延分开报告。

## 5. 灰度门槛

### 只读灰度

- 个人信息已脱敏或已获授权；
- Side-effect False Allow 为 0；
- 所有 Observation 可追溯到时间、会话和原文；
- 断线、验证码和风险页面能停止并交还人工；
- 不自动发送任何外部消息。

### 发送 canary

只有在只读灰度稳定后才允许进入：

- 仅限明确白名单测试会话；
- 每次发送都有未过期且范围完全匹配的审批令牌；
- 发送前重新 Fresh Capture，确认页面、会话、收件人和草稿未变化；
- 每次发送写入不可混淆的审计事件；
- 任一异常立即停止，不自动重试发送。

## 6. Bad Case 回归

Bad Case 进入独立回归集，保留原始输入、错误输出、根因、修复策略和期望结果。修改 Prompt、模型、规则、工具 Schema 或浏览器适配器后，同时运行冻结主测试集和 Bad Case 集。

不能只在修改后的样本上验证，也不能因为模型版本变化而重新抽取一套更容易通过的 Gold。
