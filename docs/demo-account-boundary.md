# 真实账号与演示边界

## 当前结论

基础 Demo 不需要真实 BOSS 招聘账号。项目先用虚构 Fixture 和 Mock Browser 展示招聘对话的 Observation、Agent 决策、原文证据和人工审批流程。

## 后续真实账号条件

如需展示招聘方视角，账号必须通过合法申请或由有权限的企业主体明确授权。以下步骤不能自动化绕过：

- 手机号和实名验证；
- 企业或招聘者身份认证；
- 二维码登录；
- 验证码；
- 平台风险提示或限制。

不得为了 Demo 创建虚假企业、使用他人身份信息或绕过平台控制。

## 接入顺序

1. 明确账号主体、授权人和演示用途。
2. 人工完成注册、认证和首次登录。
3. 只读采集一个脱敏测试会话，验证 DOM/截图和会话身份。
4. 运行只读灰度，不发送消息。
5. 评审隐私、平台规则、动作审计和停止条件。
6. 仅在明确授权后测试一条人工审批发送链路。

## 演示数据

公开仓库、测试报告和截图只能使用虚构或脱敏数据。真实 Cookie、Local Storage、电话号码、简历、公司内部信息和聊天内容不得进入 Git 或公开演示工件。
